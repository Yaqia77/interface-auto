# 接口自动化测试程序 v1 实施方案

## Context

用户需要一款 Excel 驱动的接口自动化测试程序：接口内容从指定目录的 Excel 文件读取，运行结束生成测试报告。初版以代码（CLI）方式运行，页面版留待 v2 迭代。项目为全新空目录 `f:\crud\interface-auto`。

已确认的决策：
- 被测对象：公开演示 API（httpbin.org + jsonplaceholder.typicode.com），零环境依赖
- 鉴权链路：Token 放 Header（登录用例提取 token → 后续用例 `{{token}}` 引用）
- 数据库断言：v1 不做，仅 HTTP 响应断言
- CI 集成：v1 不做，本地 CLI 运行

## 技术栈

| 层面 | 选型 |
|---|---|
| 语言 | Python 3.10+ |
| HTTP | requests |
| Excel | openpyxl |
| 框架 | pytest |
| 提取 | jsonpath-ng |
| 报告 | pytest-html + allure-pytest（双报告） |
| 配置/日志 | PyYAML + loguru |

依赖清单（requirements.txt）：requests、openpyxl、pytest、pytest-html、allure-pytest、jsonpath-ng、PyYAML、loguru

## Excel 模板设计（data/api_cases.xlsx，3 个 Sheet）

### Sheet1「用例」一行一条用例

| 列 | 字段 | 必填 | 说明 |
|---|---|---|---|
| A | case_id | ✅ | 用例唯一编号（如 login_001），重复则报错 |
| B | module | ✅ | 模块名，报告分组用 |
| C | api_name | ✅ | 接口名称 |
| D | case_desc | ✅ | 用例描述 |
| E | priority | ✅ | P0~P3 |
| F | run | ✅ | Y/N，N 跳过（报告中显示 skipped） |
| G | method | ✅ | GET/POST/PUT/DELETE/PATCH |
| H | url | ✅ | 完整 URL（http 开头）直接使用；相对路径则拼接环境 base_url |
| I | headers | ❌ | JSON 对象，与环境默认头合并（用例优先） |
| J | params | ❌ | JSON 对象，URL 查询参数 |
| K | body | ❌ | JSON 请求体 |
| L | extract | ❌ | JSON 对象：`{"变量名":"$.json.path"}`，提取响应字段供后续用例使用 |
| M | assert | ✅ | JSON 数组：`[["操作符","取值路径","期望值"],...]` |
| N | timeout | ❌ | 秒，缺省用全局配置 |

**断言操作符**：eq / neq / contains / gt / ge / lt / le / regex / not_null / len_eq
**取值路径**：`status_code`（状态码）、`response_text`（响应原文）、`$.xxx`（响应体 JSONPath，`$` 为整个 body）
**期望值支持 `{{变量}}`**（如 `[["eq","$.id","{{post_id}}"]]`），可实现"查询结果与上一步创建的 ID 一致"类断言。

### Sheet2「全局变量」

| 变量名 | 值 | 备注 |
|---|---|---|

变量查找优先级：运行时 extract 提取值 > Sheet2 > config.yaml 环境变量

### Sheet3「填写说明」

内置字段含义、断言语法、示例，面向用例维护者。

## 目录结构

```
interface-auto/
├── config/config.yaml        # 环境配置
├── data/api_cases.xlsx       # 接口用例
├── core/
│   ├── models.py             # TestCase 数据类
│   ├── excel_loader.py       # Excel 解析 + 格式校验（报错定位到行列）
│   ├── context.py            # 变量池（优先级合并）
│   ├── variable.py           # {{var}} 替换引擎（url/headers/params/body/断言期望值）
│   ├── http_client.py        # requests 封装（超时、报文快照）
│   ├── extractor.py          # jsonpath-ng 变量提取
│   ├── asserts.py            # 断言引擎（10 个操作符，失败输出实际值 vs 期望值）
│   └── runner.py             # 单用例执行编排
├── tests/
│   ├── conftest.py           # pytest 自定义参数 --env/--file/--module/--priority/--keyword
│   └── test_api.py           # pytest_generate_tests 参数化，保持 Excel 行顺序（串行）
├── tools/gen_template.py     # 生成/重置 Excel 模板 + 9 条演示用例
├── main.py                   # CLI 入口（组装 pytest 参数 + 时间戳报告目录）
├── reports/                  # 每次运行一个时间戳目录：report.html + allure-results/
├── logs/
└── requirements.txt
```

## 核心逻辑

1. **执行链路**：加载 YAML → 解析 Excel（校验）→ pytest 参数化（严格按行序，不并行，保证依赖）→ 逐条执行：变量替换 → 发请求（记录完整报文）→ 变量提取写入变量池 → 断言 → 结果留痕 → 双报告 → 控制台汇总
2. **接口串联**：extract 提取的变量存入变量池，后续任意用例通过 `{{var}}` 引用；Sheet2/YAML 变量可被运行时提取值覆盖
3. **格式校验**：case_id 唯一性、method 合法性、JSON 列可解析、assert 格式合法；报错格式如 `[api_cases.xlsx → 用例Sheet 第7行 K列 body] JSON 解析失败: ...`
4. **CLI**：`python main.py --env test --file data/api_cases.xlsx --module 用户模块 --priority P0 --keyword 登录`（--file 支持目录，合并目录下所有 xlsx）
5. **config.yaml**：

```yaml
default_env: test
env:
  test:
    base_url: https://httpbin.org
    timeout: 15
    default_headers:
      User-Agent: interface-auto/1.0
report:
  html: true        # reports/<ts>/report.html（单文件，双击可看）
  allure: true      # reports/<ts>/allure-results/
log:
  level: INFO
  save_payload: true  # 每用例完整请求/响应报文入日志与报告
```

6. **v2 页面版预留**：core/ 纯逻辑无 CLI 依赖，可直接被 FastAPI 调用；Excel 三 Sheet 与未来 DB 表（用例/变量/配置）一一映射

## 实施步骤

1. 环境检查：确认本机 Python 3.10+（用户机器为 Windows，注意用 pathlib 处理路径）
2. 项目骨架：requirements.txt、config/config.yaml、core/、tests/、reports/、logs/ 目录
3. core/models.py + context.py + variable.py：数据类、变量池（优先级合并）、{{var}} 替换
4. core/excel_loader.py：解析 3 个 Sheet + 全量格式校验
5. core/http_client.py + extractor.py：请求封装、jsonpath 提取
6. core/asserts.py：断言引擎（10 操作符，实际值 vs 期望值对比输出）
7. core/runner.py：单用例编排（替换 → 请求 → 提取 → 断言 → 留痕）
8. tests/conftest.py + test_api.py：pytest 参数化入口，保持行序
9. main.py：argparse CLI + 时间戳报告目录 + pytest.main 调用
10. tools/gen_template.py：生成含 9 条演示用例的 Excel 模板
11. 端到端联调：真实请求 httpbin + jsonplaceholder，修通全部用例
12. 报告验证：HTML 报告、Allure 结果、失败用例的报文与断言明细展示

## 验证方式

```bash
pip install -r requirements.txt
python tools/gen_template.py                      # 生成 data/api_cases.xlsx
python main.py --env test --file data/api_cases.xlsx
```

预期结果：
- 9 条用例：8 条 passed、1 条 skipped（skipped_001）
- reports/<时间戳>/report.html 生成，双击可查看，每条用例含完整请求/响应报文
- reports/<时间戳>/allure-results/ 生成（本机装有 allure 命令行时 `allure serve` 可看增强版）
- 手工破坏一条断言期望值（如把 200 改成 201）重跑，报告能清晰展示"实际值 200 vs 期望值 201"及完整报文
- 验证筛选：`python main.py --module 演示-文章CRUD` 仅执行该模块 3 条
- 验证校验：在 Excel 中制造一处 JSON 格式错误，重跑应报出精确行列位置
